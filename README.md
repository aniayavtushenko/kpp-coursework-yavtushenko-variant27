# Інформаційна система бронювання наукового обладнання (Варіант №27)

Клієнт–серверна інформаційна система на Java 21 (Maven, JavaFX, Servlet API, Apache Tomcat 9.x, MySQL) призначена для обліку наукового обладнання, реєстрації дослідників, оформлення заявок на бронювання та фіксації записів фактичного використання приладів. У системі реалізовано чотири ключові сутності — обладнання (`Equipment`), дослідники (`Researcher`), бронювання (`Booking`) та записи використання (`UsageRecord`). Через графічний JavaFX-клієнт користувач може переглядати дані, виконувати CRUD-операції, перевіряти предметну логіку (розрахунок інтегрального показника ризику та чотиристанний життєвий цикл бронювання `CREATED → APPROVED → ACTIVE → CLOSED`) і запускати фоновий імпорт реєстру обладнання з CSV-файлу.
## Технології
* **Java 21** — основна мова програмування для серверного (`server`) та клієнтського (`client`) модулів.
* **Maven** — керування залежностями та складання проєкту: **Maven War Plugin 3.4.0** формує `scientific-equipment-server.war`, **Maven Surefire Plugin 3.5.2** запускає тести під час збірки, а **JavaFX Maven Plugin 0.0.8** запускає клієнт (`ua.edu.nupp.kpp.client.MainApp`).
* **JavaFX 21.0.2** (`javafx-controls`) — графічний інтерфейс користувача та фоновий імпорт CSV через `Task`.
* **Servlet API 4.0.1** (`javax.servlet-api`) — обробка HTTP GET/POST-запитів на сервері.
* **Apache Tomcat 9.x** — вебконтейнер, у якому розгортається та запускається `scientific-equipment-server.war`.
* **JDBC / MySQL Connector/J 9.7.0** — підключення та робота з реляційною базою даних MySQL (`scientific_equipment`).
* **Jackson Databind 2.18.2** — перетворення об’єктів у формат JSON і назад під час обміну між клієнтом і сервером.
* **JUnit 5 (`junit-jupiter` 5.11.4)** — автоматизоване виконання модульних тестів.
* **Git** — контроль версій та робота з репозиторієм на GitHub.
## Структура проєкту
* `README.md` — коротка інструкція зі структури, складання та запуску системи.
* `database.sql` — SQL-скрипт для створення бази даних `scientific_equipment`, чотирьох таблиць і початкових демонстраційних даних.
* `server/` — серверний Maven-модуль (`pom.xml`, `web.xml`, моделі, DAO/JDBC, сервісна бізнес-логіка, розрахунок інтегрального показника, контроль життєвого циклу та HTTP/JSON-сервлети).
    * `server/src/test/java` — модульні тести JUnit 5 для перевірки розрахунків, переходів станів і валідації.
* `client/` — клієнтський Maven-модуль (`pom.xml`, графічний інтерфейс JavaFX, HTTP-клієнт і фоновий імпорт через `Task`).
    * `client/sample-data` — приклад CSV-файлу (`equipment.csv`) для фонового імпорту реєстру обладнання.
  ## Підготовка бази даних
1. Запустіть локальний сервер MySQL (або MySQL-сумісну СУБД) та переконайтеся, що він доступний для з’єднання.
2. Виконайте кореневий скрипт `database.sql` (наприклад, через клієнт командного рядка MySQL, MySQL Workbench або інструмент імпорту phpMyAdmin), зберігши назву бази даних `scientific_equipment`.
3. Перевірте наявність таблиць у базі `scientific_equipment`: мають бути створені `equipment`, `researcher`, `booking` та `usage_record` із початковими даними.
4. За потреби адаптуйте локальні параметри підключення (адресу/порт БД, ім’я користувача та пароль) у класі `DBUtil` на своєму комп’ютері — не зберігайте конфіденційні паролі в репозиторії.
## Запуск сервера
Команди Maven виконуються саме з каталогу `server` (де розташований `server/pom.xml`), а не з кореневого каталогу без вказування модуля.

1. Перейдіть у каталог серверного модуля:
   ```bash
   cd server
   
  2. Запустіть модульні тести JUnit 5 і зберіть WAR-архів:
   ```bash
   mvn clean test
   mvn clean package
   ```
3. Скопіюйте сформований файл `server/target/scientific-equipment-server.war` у каталог `webapps` вашого **Apache Tomcat 9.x** та запустіть Tomcat (`bin/startup.bat` у Windows або відповідний скрипт запуску).
4. Відкрийте у браузері контрольну адресу:
   `http://localhost:8080/scientific-equipment-server/equipment`
5. **Перевірка успіху:** браузер повертає JSON-масив обладнання, у журналі/консолі Tomcat немає помилок розгортання, а сервер має підключення до MySQL (`scientific_equipment`) і коректно зчитує дані.
## Запуск JavaFX-клієнта
JavaFX-клієнт не працює автономно без сервера: перед його запуском мають бути запущені **MySQL**, **Apache Tomcat 9.x** із розгорнутим WAR-архівом і перевірений GET-маршрут API (`http://localhost:8080/scientific-equipment-server/equipment`).

1. Перейдіть із кореня репозиторію до каталогу клієнтського модуля (якщо термінал уже в `client`, повторювати `cd client` не потрібно):
   ```bash
   cd client
   ```
2. Запустіть JavaFX-додаток через Maven:
   ```bash
   mvn javafx:run
   ```
3. Клієнт надсилає HTTP-запити за адресою `BASE` у класі `HttpEquipmentClient` (`http://localhost:8080/scientific-equipment-server`). Якщо виникає помилка підключення або `404`, спочатку перевірте, чи запущений Tomcat, чи розгорнуто `scientific-equipment-server.war` і чи збігається контекстний шлях та порт із `BASE`.
4. **Робочий каталог для CSV-імпорту:** відносний шлях `sample-data/equipment.csv` відраховується від робочого каталогу `client`, тому запускати застосунок потрібно саме з каталогу `client` (або з коректно заданим working directory `client`).
## Тестування
Модульні тести **JUnit 5** розташовані в каталозі `server/src/test/java` (`CourseworkTest`) та перевіряють предметну логіку без запуску JavaFX, Tomcat чи бази даних:

1. Перейдіть у каталог серверного модуля:
   ```bash
   cd server
   ```
2. Запустіть набір тестів через Maven (`mvn test` або з попереднім очищенням `mvn clean test`):
   ```bash
   mvn clean test
   ```
3. **Основні перевірені правила (варіант №27):**
    * розрахунок фактора $F_1$ за дедлайном та обробка некоректного формату дати;
    * обчислення інтегрального показника $I = 0{,}40 \cdot F_1 + 0{,}35 \cdot F_2 + 0{,}25 \cdot F_3$ та перевірка меж факторів (`0..100`);
    * дозволені та заборонені переходи чотиристанного життєвого циклу бронювання (`CREATED → APPROVED → ACTIVE → CLOSED`);
    * валідація вхідних даних сервісного рівня для бронювань, обладнання та дослідників.
4. За результатами фактичного запуску виконується **12** модульних тестів (`Tests run: 12, Failures: 0, Errors: 0, Skipped: 0`). Якщо склад тестів у коді змінюватиметься, цю кількість і опис слід оновити разом із тестовим класом[cite: 1, 2, 3].
5. Згенеровані звіти з `target/surefire-reports` не додаються до документації чи репозиторію — кожен користувач отримує їх власним запуском Maven.
## CSV-імпорт
Фоновий імпорт реєстру обладнання виконується у клієнтському модулі через JavaFX `Task` (`ImportEquipmentTask`) з відносним шляхом `sample-data/equipment.csv` (відносно робочого каталогу `client`), кодуванням **UTF-8** та роздільником значень — **комою (`,`)**. Кожен коректний рядок із чотирма полями (`inventory_code`, `name`, `category`, `utilization_percent`) передається на сервер через HTTP-запити (`HttpEquipmentClient` → `Servlet` → `Service` → `DAO/JDBC` → `MySQL`), а не через прямий JDBC-зв’язок із клієнта.

1. Запустіть MySQL, сервер в Apache Tomcat 9.x та JavaFX-клієнт з каталогу `client` (`mvn javafx:run`).
2. Відкрийте вкладку **«Обладнання»** (або потрібну вкладку зі списком/імпортом) та натисніть кнопку **«Імпортувати CSV»** (за потреби для переривання доступне скасування).
3. Простежте за індикатором прогресу (`ProgressBar`), текстовим статусом виконання та оновленням таблиці після завершення (на контрольному наборі додаються нові записи та оновлюється загальна кількість у таблиці і БД).
4. **Обмеження при повторному імпорті:** якщо у поточній версії реалізації немає спеціальної перевірки дублікатів (або при частковому збереженні рядків до помилки чи скасування), повторний запуск імпорту того самого файлу може призвести до повторного додавання рядків або залишення вже збережених у базі записів; перед повторною перевіркою варто контролювати стан даних у `scientific_equipment`.
